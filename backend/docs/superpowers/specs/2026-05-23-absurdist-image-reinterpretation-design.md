# 荒诞派原图转译提示词改造设计

## 目标

将 MoodCanvas 当前的“根据情绪生成全新抽象画”调整为“以用户上传图片为视觉依据，将原场景转译为荒诞派作品”。输出图片应尽量保持原图中可辨识的主体、大体轮廓、构图关系与关键元素，同时通过非现实尺度、材质、空间和叙事关系产生荒诞感。

## 本次范围

- 仅修改 `mood-canvas/app/prompts/mood_art.py` 中供视觉分析模型使用的系统提示词，并同步更新外层测试所覆盖的镜像入口 `../app/prompts/mood_art.py`，避免从两个可启动目录运行时出现不同效果。
- 保持现有 `glm-4v-flash` 图片理解和 `cogview-3-flash` 图片生成调用方式不变。
- 保持接口、响应结构、前端交互和五张候选图流程不变。
- 增加针对提示词行为约束的测试，验证核心要求不会在后续修改中丢失。

## 已知边界

当前流程中，上传图片只发送给视觉分析模型；图片生成模型收到的是分析模型生成的文本 prompt，而不是原图本身。因此，本次改造能通过更准确的场景描述和强约束提升主体与构图延续性，但不能提供严格的图生图一致性。

若后续仍无法达到用户对结构保持和画面精度的要求，应另立需求，引入能够直接接收参考图的图片编辑或图生图模型。

## 提示词策略

### 角色定位

系统角色调整为荒诞派/超现实叙事的视觉重构导演：不是从情绪出发另创场景，而是在原照片基础上进行有控制的非现实转译。

### 原图锚点

分析阶段必须先识别并在每条生成 prompt 中保留：

- 主要主体及其数量。
- 主体的大体轮廓、姿态或方向。
- 关键物体及其相对位置。
- 原始视角、主体占画面比例和核心构图布局。
- 仍需在生成结果中能被识别出的场景元素。

### 荒诞化规则

在不移除锚点的前提下，允许：

- 不合常理的尺度变化与比例悖论。
- 悬浮、融化、穿透、错位、循环等非现实物理关系。
- 舞台化光影、梦境空间、象征性材质和不安但诗意的叙事。
- 将用户情绪映射为色彩、气氛与荒诞事件。

参考效果进一步限定为叙事性厚涂油画：保持原照片的摄影透视、物件位置和画幅方向，将日常物件转化为舞台或庞大景观；以深蓝夜色、暖金灯光、明显的油画笔触和少量微缩人物建立荒诞尺度感。微缩人物仅作为点景，不能替代或遮蔽原图主体。

提示词内部先建立两个创作变量：`INPUT_ELEMENTS` 用于锁定包装颜色、形状、位置和可识别细节，`USER_MOOD` 用于驱动色彩、压迫感或黑色幽默等情绪隐喻。五张候选图共享这两个变量，但分别投射到古典歌剧院、荒凉沙漠、星空废墟、折叠室内剧场和荒诞仪式五类反差环境中。

明确禁止：

- 用完全不同的主体替换原主体。
- 删除关键元素或把构图打散为与原图无关的新画面。
- 只描述抽象色块与笔触而忽略原场景内容。

### 五张候选图

五张作品共享同一组原图锚点，但使用不同的荒诞手法，例如尺度悖论、物体错位、空间折叠、材质异化和时间凝固。候选图之间的区别来自转译方法，不来自任意替换原始内容。

### 生图 Prompt 约束

每条英文 prompt 以 `Absurdist surreal reinterpretation of the original scene,` 开头，并显式包含以下意图：

- preserve the recognizable main subject and silhouette
- preserve the original composition and spatial relationships
- keep the key objects identifiable
- introduce a controlled absurdist transformation rather than inventing a different scene

## 数据流

1. 用户上传图片并输入情绪文本。
2. `glm-4v-flash` 读取图片和文本，识别视觉锚点与情绪语境。
3. 模型返回五条含锚点约束与不同荒诞手法的英文图片生成 prompt。
4. `cogview-3-flash` 依据这些文字 prompt 生成五幅候选图。
5. 前端仍展示五幅作品供用户选择。

## 测试

在外层已有 `tests/test_prompts.py` 中增加提示词级回归测试，确保：

- 系统提示词包含荒诞派转译方向。
- 系统提示词明确要求保留主体、轮廓、构图、空间关系和关键物件。
- 系统提示词不再要求所有 prompt 以 `Abstract painting,` 开头，而要求以荒诞转译前缀开头。
- 用户上传图像仍被 `build_messages` 作为视觉输入发送给分析模型。
- 两个可启动入口均保有相同的荒诞派与原图锚点约束。

## 验收标准

- 不改变 API 契约即可运行现有流程。
- 分析模型生成的五条 prompt 明确以原图结构为基础，并各自提出一种荒诞化方式。
- 代码中可自动验证关键提示词约束存在。
- 清晰告知用户：仅改提示词可改善但不能保证严格复刻原图结构。
